### C-01: mobile layout rationale

The off-board source contains a 678px introduction, 920px plan group and 587px empty BMI frame. The 2305px total is approximately 24% of the mobile board's height; this is source geometry, not a measured runtime page. Compact plan cards keep both offers visible; an inline BMI disclosure lets interested users expand the full form without leaving the page. Do not split the three parts into mutually exclusive tabs, hide the entire service, or force a scroll jump on expansion. A default section height of roughly 1100–1400px is an initial design budget, not a fixed height or verified result. P5 measured the 375px implementation at 1407.7px from the Weight Loss introduction through the collapsed BMI, including the intervening 56px gap. This is about 897px shorter than the source-only 2305px stack; it is not a fixed height. Both offers remain visible. The original P5 delivery withheld the Semaglutide thumbnail; the subsequent owner decision approves shared vial artwork under C-12.

This applies general findings from [NN/g on mobile accordions](https://www.nngroup.com/articles/mobile-accordions/), [GOV.UK's tab guidance](https://design-system.service.gov.uk/components/tabs/) and [Baymard's mobile product-page research](https://baymard.com/research-articles/avoid-horizontal-tabs). They support keeping comparison content visible and making secondary content optional; they are not Apsu-specific user-test results.

### Language interaction follow-up (owner decision, 2026-09-17)

The language chips look interactive, but previously had no response. The owner authorizes local selection toggles as a component demonstration even without a business destination or callback. Preserve the source initial highlights; clicking a language toggles its state without translating the page. Loop copies must mirror the same state and stay outside duplicate keyboard/screen-reader navigation. Keyboard interaction exposes a static wrapping list.

Both running strips previously stayed paused after Resume and pointer exit because the clicked button retained focus and matched :focus-within. Pause only for visible keyboard focus in keyboard input mode, retaining pointer hover pause and persistent Pause. Track the real input source because Chromium can retain :focus-visible when switching from keyboard to pointer; do not blur the control to conceal the issue. Ten targeted browser cases pass at 375/1440, including normal/reduced page axe; twenty affected stories pass both widths (40 checks). Pointer copies and touch selection share state; touch Resume runs immediately after release.
